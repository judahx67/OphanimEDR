Provenance Graphs

From Zero to Hero: Understanding system causality and forensic tracing

A provenance graph is a directed acyclic graph (DAG) that captures who caused what in a computer system, preserving the complete causal history of events.

1. What is Provenance?

Provenance means origin and history of creation. In the context of operating systems and cybersecurity, provenance refers to the complete causal chain of events that led to a particular state.

Why Provenance Matters

Consider a malware infection. A traditional security alert might say: Suspicious file write detected in C:\Windows\System32

But this raises critical questions:

  • Who wrote to that location?
  • Why did they do it?
  • What were the earlier steps that led to this event?
  • What came after? (impact assessment)

Provenance graphs answer all of these. By tracking every event (process creation, file reads/writes, network connections) and linking them causally, you create a forensic record that reveals the entire attack chain.

Key Insight: "Who Caused What, and When"

Every system event has prerequisites (what made it possible) and consequences (what it enabled). Provenance preserves these cause-effect relationships.

2. The Building Blocks

A provenance graph has two core components: nodes (system entities) and edges (causal relationships between them).

Nodes: What Can Be Entities?

In OS-level provenance, nodes represent system resources. The main types are:

◉

Process

Running program instance

▭

File

Data at rest on disk

◇

Socket

Network endpoint

⬡

Registry

System configuration

Process

A process is a running instance of a program. Each process has a unique ID (PID), owns memory, file handles, and can perform actions like reading files or creating network connections.

Edges: How Are They Connected?

Edges represent causality between nodes. An edge always points from cause to effect. Common edge types include:

  • WRITE: Process wrote to a file or registry
  • READ: Process read from a file
  • EXECUTE: Process executed a binary
  • FORK: Process created a child process
  • CONNECT: Process connected to a network socket
  • SEND: Process sent data over a socket

Each edge is timestamped, meaning we know the exact moment the event occurred. This ensures edges always point forward in time: the source node's timestamp is always earlier than the destination node's timestamp.

3. Causality: The Heart of Provenance

Causality is the core concept. Event B is caused by Event A if:

A happened first, AND
The output of A became the input to B.

Example: A process reads a file's contents. The act of reading is caused by the file's existence and the process's decision to open it.

Why Directed Edges?

By directing edges from cause to effect, we create a dependency chain. If you follow an edge backward, you're asking "what made this possible?" If you follow forward, you're asking "what did this enable?"

This structure is called a Directed Acyclic Graph (DAG) because:

  • Directed: Edges have direction (cause → effect)
  • Acyclic: No cycles (can't go back in time)
  • Graph: Nodes and edges structure

Temporal Ordering

The timestamp on each event ensures correct temporal ordering. You cannot have an edge from a later event to an earlier one — causality always flows forward in time.

5. Forward & Backward Analysis

Provenance graphs enable two powerful forensic techniques:

Backward Tracing (Root Cause Analysis)

Question: "How did we get here?"
Method: Follow edges backward from a suspicious node.

Example: You find suspicious registry modifications. By tracing backward, you discover: 

Registry change ← cmd.exe ← word.exe ← invoice.docx

Now you know the infection came through a malicious Office document!

Forward Tracing (Impact Assessment)

Question: "What did this compromise?"
Method: Follow edges forward from a compromised node.

Example: You realize cmd.exe was compromised. By tracing forward, you see: 

cmd.exe → Network socket → exfiltration
cmd.exe → Registry key → persistence
cmd.exe → Other files → lateral movement

Now you understand the full scope of the attack!

6. Why Graphs? The Power of Structure

You might ask: "Why not just use a log file?" Let's compare:

Aspect Flat Log Provenance Graph
Question: "What happened?" Lists all events sequentially Shows cause-effect relationships
Example output: cmd.exe wrote to registry
word.exe opened file
cmd.exe connected to socket 		Shows that word.exe → cmd.exe → registry in one visual chain
Backward tracing: Must manually search logs, context-switching Follow edges backward efficiently
Multi-hop relationships: Hard to see (5+ hops requires reading many logs) Immediately visible in the graph structure
Visual understanding: Sequential only; hard to see global patterns Graph visualization reveals attack structure
Computational efficiency: Linear search through all logs Fast graph queries (find all ancestors, descendants, paths)

Key Properties of Graphs

  • Transitivity: If A caused B and B caused C, then A transitively caused C
  • Temporal Ordering: Edges respect the arrow of time
  • Multi-hop Detection: Find long attack chains in seconds
  • Actionable Structure: Graph algorithms enable threat hunting at scale

7. Summary: Key Terms & Concepts

Congratulations! You now understand the fundamentals of provenance graphs. Here's a quick reference:

Provenance

Complete causal history of how a system reached its current state.

Subject

The entity performing an action (usually a process).

Object

The entity being acted upon (file, socket, registry, etc.).

Event

A single action at a specific timestamp (e.g., "process wrote to file").

Node

A system entity in the graph (process, file, socket, registry).

Edge

A directed link representing causality between two nodes.

Dependency Chain

A sequence of edges showing how one event led to the next.

Forward Analysis

Tracing forward from a compromised node to assess impact.

Backward Analysis

Tracing backward from a suspicious event to find the root cause.

Temporal Ordering

Property that edges respect the flow of time (no cycles).

DAG

Directed Acyclic Graph — the mathematical structure of provenance.

Threat Hunting

Using provenance graphs to proactively discover and investigate attacks.
